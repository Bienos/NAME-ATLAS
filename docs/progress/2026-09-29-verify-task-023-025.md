## Found, not fixed

1. **The share card makes a false statement about a listed surname whose figures are not derived.**
   - `apps/web/src/lib/og-facts.ts` turns every population state other than READY and RIGHTS_BLOCKED into "Zbiór nie podaje liczby dla tego nazwiska" / "The dataset publishes no count for this surname".
   - For UNAVAILABLE with `NOT_DERIVED_YET` (ŻYWUSKI) that is untrue: the dataset does publish a count. The page says correctly that the figures are not prepared yet. `3fbd477` fixed that wording on the page but not on the card.
   - Production is not affected today, because its seven surnames are derived and nothing else is loaded. It will show wherever the register is loaded with only part of it derived.
2. **TASK-023 AC-1 and AC-8**, as described above. For each, the project owner can amend the criterion or change the page.
3. **The not-found page does not explain unpublished surnames.** The page for a surname in none of the files (Qwertyuiopski) says "Nie znaleziono takiego nazwiska. Nie znaleziono dostatecznie podobnego nazwiska." and shows no zero. It does not say that a surname borne by one person is not published. None of these three tasks' criteria asks it to.
