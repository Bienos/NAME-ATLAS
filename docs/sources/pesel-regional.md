## Verdict

**The approved production source does not contain surname distribution by geography.** The approved ingestion target (TASK-004) is the national resource pair `1148808`/`1148811`: two columns, no geographic field, portal `regions = Polska`. A current, official, dated **candidate** regional pair exists on the same dataset (`1148786`/`1148790`) but it is explicitly unadopted (D-004 open; TASK-004 §8 excludes it; `PRODUCT.md` §10: "no lawful, genuinely current regional dataset is established"), its resource-level licence is unconfirmed, its suppression and reconciliation semantics are unverified, it carries **no administrative code of any kind**, and the repository has no `Place`, no external-ID table, no TERYT data, no `DistributionSnapshot` table, no `Claim` table and no truth-chain code. A `CURRENT_DISTRIBUTION` task written today would have to invent geographic identity, guess suppression semantics and build a parallel truth system — each of which the request forbids.

## Proposed smallest prerequisite task — PESEL regional source spike

**Not created as a task file.** The repository specifies one task at a time and TASK-004 is specified but unimplemented; the number and the go-ahead are the project owner's. The proposal is recorded here so it can be lifted into `tasks/` verbatim when approved.

**Goal.** Establish, from the actual bytes and with a small real fixture, exactly what the two regional resources contain — so that D-004 can be decided on facts and a later ingestion task can be specified without guessing. The pattern is TASK-002 (`tasks/002-pesel-source-spike.md`), applied to `1148786`/`1148790`.

**Preconditions.** The project owner supplies the two CSV files (from `NAME_ATLAS_ALL_DOWNLOADED_DATA.zip` or a fresh download); the session verifies them against the SHA-256 values in `fixtures/pesel/source-manifest.json` before reading anything. Network egress to `dane.gov.pl` is not assumed. D-004 stays open; the spike informs it and does not decide it.

**In scope.**

1. Byte-level verification, mirroring `docs/sources/pesel.md` "File-level facts": checksum, size, encoding, BOM, delimiter, quoting, line endings, header, column count, row count, sort order, malformed rows, Unicode notes.
2. **Geography column:** the complete list of distinct values with exact spelling and per-value row count; whether the set is exactly the current voivodeships or includes any other category; whether any value differs between the two files.
3. **Suppression and zero:** minimum and maximum `Liczba`; presence of `0` or `1`; whether the exclusion rule is applied per cell or nationally, established by comparing per-surname regional sums against the same surname's count in the same-sex **national** resource (already fixtured and checksummed) — recorded as the observed relationship (equal / lower / higher, how often, by how much), which is the only honest basis for a reconciliation invariant.

5. **Rights:** record the outcome of the publisher confirmation request for resource-level licence (or that it is still pending); do not mark anything approved.
6. **Geographic identity groundwork, evidence only:** from the TERYT TERC data (the archive's `teryt_terc` zip, checksum-verified against `SHA256SUMS.txt`, or an official GUS download), record the current voivodeship TERC codes and official names alongside the strings observed in item 2, with the mapping's provenance. 7. **Fixtures:** `fixtures/pesel/regional-male-2026-01-20.csv` and `regional-female-2026-01-20.csv`, real rows only, verbatim, selected by a documented method (several voivodeships for one common surname; the smallest observed `Liczba`; diacritic, foreign-script and artefact rows where present); `fixtures/pesel/source-manifest.json` regional entries extended with the verified file facts, still under `regional_resources_not_ingested`.
